    Specification Status¶

    User-facing configuration pages describe the current source tree. Specifications also preserve proposals and design decisions; a draft is not an installed-binary configuration reference.

    Implemented¶

    Specification Status
    A stable prompt prefix Implemented (2026-10-29, five phases; client protocol 1.53.0 and 1.54.0); the agent can set a goal (goal_set, goal tools in every root run), one loader tool (tool_search finds and loads, select: for exact names), the cron, agents, runtimes, goal, and memory groups deferred ([deferred_tools] always_load), tool rounds for every model, tool names pinned for a round, and on deferring models a system prompt whose runtimes, tool-instruction, and skills blocks are frozen per round with <instructions_changed> announcements
    The user's shell environment for runtimes Implemented (2026-10-28; runtime protocol 1.12.0); runtimes capture the user's shell environment ([shell_environment] capture, default interactive ($SHELL -l -i), off to disable, per runtime under [runtimes.<id>.shell_environment]) and start the bash tool's commands, MCP servers, ACP agents, plugins, and template commands in it; a bash snapshot of options, aliases, and functions sourced before each bash command; captured again on settings changes and config.reload; failed captures and runtimes too old to capture in the configuration diagnostics
    Unread sessions and selecting several sessions Implemented (2026-10-28; client protocol 1.51.0); a root session that settles, or whose tree waits on an approval or a question, while nobody is present on its tree is unread (<data_root>/unread.json, kept across restarts) until a client is present on it or the user marks it read; a bubble in both clients, session.unread.set, and the web's session list selecting several sessions to mark read, mark unread, or delete (skipping running ones)
    Sign in with ChatGPT as a provider Implemented (2026-10-28; client protocol 1.49.0, oven-sdk 61361b4); a built-in chatgpt provider ("Codex / ChatGPT") on OpenAI's official Sign in with ChatGPT token sharing: browser sign-in from the TUI, cookie connect, and the web client (loopback listener, the daemon's own listener for loopback pages, paste-back), refreshing tokens beside the provider store, the plan's model list from /v1/models, the token-sharing wire profile, session-id/thread-id default headers, and in-stream compaction (compaction = "in-stream", the ChatGPT default) with the engine's checkpoint as a backstop
    Deferred tools in cookie Implemented (2026-10-27, six phases; implementation notes in section 14); generic deferral (one policy picks deferred tools, MCP and plugin tools by default), sent to models that load natively (verified, or attempted on Anthropic-compatible endpoints and gateways), tool_search and tool_load, tools announced in groups with summaries and detailed instructions on load, appended <tools_added>/<tools_removed> announcements, tool rounds (eager tools change only at compaction; mid-round arrivals are deferred, departures stay declared), compaction folding, deferred-tools.json rejection memory, always_load opt-outs, and the tools row split into provided and searchable
    Deferred tool loading in oven-sdk oven-sdk implemented (2026-10-27, oven-sdk b875054, core 0.8.0); cookie's side implemented in deferred tools in cookie; no tool_search for models without native loading, the tools row shows provided and searchable tools apart, a failed MCP server is reconnected before a tool loaded from it is dropped, Anthropic-compatible endpoints get deferral tried and fall back on rejection, and MCP and plugin tools are always deferred where supported, with appended <tools_added>/<tools_removed> announcements a per-server and per-tool always_load, and compaction folding loaded tools into the eager tool prefix (after an internal summary, which keeps its cache, and before an OpenAI native compaction, whose window otherwise leaves them unusable); one provider-neutral way to defer a tool and to load it from a tool result, encoded natively for Anthropic (defer_loading and tool_reference), OpenAI Responses (an additional_tools input item, verified live, whose loaded tools' calls carry a namespace replay must keep), and Kimi K3 and Kimi Code (a system message carrying tools, as Moonshot's Kimi Code client sends it), with every tool sent up front elsewhere
    ACP v2: the port, self-wakes, subagent sessions, and background work Implemented (2026-10-26; client protocol 1.40.0, plugin protocol 1.21.0); cookie speaks only ACP v2 and refuses v1-only agents at initialize; runs end by the agent's state_update and steering is a prompt during work; work the agent starts on its own is a run started by an acp_agent producer message; the agent's subagents are nested child sessions (how: subagent) that report nothing and take no prompts; commands left running after their calls ended are background calls (agent_task) that keep the agent's process and session alive
    Thinking-replay recovery Implemented (2026-10-26; client protocol 1.33.0); a request Anthropic refuses because a replayed thinking block is bound to a changed prefix (tools or system prompt) is retried once without the earlier reasoning, and native_replay_cut keeps later requests from replaying it
    Held sessions Implemented (2026-10-26; client protocol 1.34.0, plugin protocol 1.19.0); a session whose run the user stopped, or whose runs failed past [model_retry] standard_retries, is held: no automatic runs, new producer messages refused (cron fires skipped, subagent reports deferred, goal reminders not made), recorded as automatic_runs_held, and cleared by session.resume (Resume in place of Send and Queue)
    Push notifications Implemented (2026-10-25); Web Push from the daemon (VAPID and RFC 8291 on aws-lc-rs, keys and subscriptions in <data_root>/push/) when a root session settles (its run ended and nothing but recurring cron jobs can wake it) and when an approval or an ACP agent's question waits; notifications.* and client.presence (client protocol 1.30.0), [notifications], the web client's Settings › Notifications and #session= links, presence from the web client and the TUI; approvals wait until answered by default ([approval] timeout_ms optional, <= 0 never expires)
    Native compaction: parallel summaries and default on Implemented (2026-10-24); native compaction runs beside the internal summary and the checkpoint keeps the window beside the summary (client protocol 1.29.0, plugin protocol 1.17.0), the window serves only its own provider and model and the summary everything else, native compaction is on by default for every Responses-API provider (compatible gateways included, oven-sdk 342a029), and providers whose compact call is unsupported or that reject windows are remembered in <data_root>/native-compaction.json and listed in the configuration status; fixes the corrupt-history failure after switching models
    Approval reviewer: context, caching, and verdicts Implemented (2026-10-24); one cached, append-only reviewer conversation per session rendered from the event log (every labelled user message, the agent's tool calls with outcomes, AGENTS.md, earlier verdicts), bounded by budgets and epochs, a rolling cache marker with [approval] cache_ttl, verdicts with a reason shown in both clients (client protocol 1.28.0, plugin protocol 1.16.0); fixes auto_approve_y approving a failed review, the reviewer's latency eating the approval window, unescaped tags, reviewer denials reading as the user's, and the permission mode resetting on restart
    Default models, the starter kit, and onboarding Implemented (2026-10-23); default_model/small_model and their variables, plain-string model entries, the starter kit (config.toml and agents) as a release asset, cookie onboard, the TUI and web setup panels, and the onboarding RPCs (client protocol 1.22.0, plugin protocol 1.10.0, runtime protocol 1.8.0); official skills kept up to date from cookie-agent/skills (section 13)
    ACP agents Implemented (2026-10-23); Claude Code, Codex, and Gemini CLI offered by runtimes as cookie agents over the Agent Client Protocol (client protocol 1.17.0, plugin protocol 1.8.0, runtime protocol 1.7.0), with cookie's tools offered to them over a runtime-relayed MCP bridge; revised 2026-10-23: no acp permission action (cookie's own bridged tools allowed at once, the agent's MCP tools as mcp, the rest to the approval flow) and delegation targets no runtime has reported yet as configuration diagnostics (client protocol 1.18.0); runtime agents, agent commands and options, the plan, and ACP tool calls in the TUI and web client; display round 2026-10-24: the agent's context use, boolean options, mode updates, command output, and images in replies (client protocol 1.23.0, plugin protocol 1.11.0); elicitation (2026-10-24): the agent's form and URL questions answered in the TUI and web client (client protocol 1.25.0, plugin protocol 1.13.0); input and pickers 2026-10-24: the agent's model and effort as the model and variant, drafts included, text and audio files, additional workspace directories, and the skill listing (client protocol 1.26.0, plugin protocol 1.14.0); the ACP agents guide. Addendum of 2026-10-25 implemented: agent documents as templates over a declaration (acp.agent), each with its own permissions (client protocol 1.32.0), and the tools cookie's bridge offers shown in the transcript's tools row
    MCP tool filters Implemented (2026-10-23); per-server include_tools/exclude_tools with */? patterns over the server's own tool names, a filtered_tools count (client protocol 1.16.0, runtime protocol 1.6.0), the TUI and web editor fields, and MCP tools offered by the merged mcp rules for their names
    Permission consolidation Implemented (2026-10-23); defaults, the agent document, and session overrides merged into one rule list per run (session rules replace by action, runtime, and pattern), used for offered tools, every call, memory, and /permissions; a broad session rule no longer beats a narrower document rule, and a session deny can hide a default-allowed tool
    Cron jobs Implemented (2026-10-23); scheduled prompts by cron expression or in <delay>, into a session (steer or queue) or a new session per run, the cron permission by target kind, list_agents, crons.* (client protocol 1.15.0), TUI /cron, the web's Scheduled prompts, and cookie cron
    Web client and local daemon use Implemented (2026-10-20); Leptos/WebAssembly client styled with Tailwind, sharing the protocol client, reducer, and panel rules with the TUI, served by cookie daemon or any static host, full TUI parity except MCP OAuth (closed 2026-10-21 by web MCP OAuth) and offering this machine as a runtime, phone layout and home-screen manifest (installable as an app with a network-only service worker since 2026-10-21, reversing "no service worker"), headless-Firefox suites in CI; plain cookie connects to a running local daemon (phase L). Addendum of 2026-10-21 implemented: web layout v2 (rail, drawer, nested subagents, the approved phone layout) and session deletion (session.delete, client protocol 1.5.0) from the TUI and the web client; web commands moved from / to the ⋮ menu, subagent tree collapsed to running agents, and a permission mode picker (2026-10-21). Addendum of 2026-10-21 on paths: canonical paths shown as ~/… under the runtime's reported home, cwd_identity from the first workspace attachment, ~/ permission rules (runtime protocol 1.3.0, client protocol 1.7.0); protocol, daemon, and TUI implemented, web display next
    MCP OAuth from the web client Implemented (2026-10-21); the page itself as the OAuth redirect with ?oauth=callback, https and localhost redirects accepted by the daemon (client protocol 1.11.0), new-tab handoff over a BroadcastChannel, paste fallback
    Delegating to runtimes Implemented (2026-10-21); a root names the runtime capabilities its subagents work through (capabilities, checked as delegate@<runtime>), list_runtimes in global, delegated attachments in the root's badges (client protocol 1.10.0), and a web New session that starts global-only; the machine registry remembers where runtimes ran (memory spec section 16.8). Addendum of 2026-10-22 implemented: offline runtimes are refused at once, open instances are handed out only over a live connection, and runtime connections are pinged and ended when silent (runtime protocol 1.4.0)
    Projects Implemented (2026-10-21); sessions belong to projects with default attachments, an AGENTS.md, and project memory in the snapshot; session rename, badges, project sections, the project editor, and the TUI's project picker in the clients
    Memory Implemented; user, agent, machine, and project memory layers as Markdown files in the global runtime, machines as a daemon concept, the memory tools and snapshot, memory.* (client protocol 1.4.0), TUI /memory, and cookie memory
    Background tool calls Implemented (2026-10-16); host-owned background calls and per-turn subagent reports. Addendum of 2026-10-22 implemented: a parent waits on a child that can still wake (its own background calls, producers, or subagents), and a producer wait alone no longer keeps a session in memory
    Runtimes Implemented; daemon as gateway with global and coding runtimes, attachments, the runtime protocol, remote runtimes from [runtimes.<id>] templates, and template MCP servers; manual labpc check (ssh template and dial-in) passed 2026-10-20; addendum of 2026-10-22 implemented: agents with no mcp key get the mode default "*": ask (section 7.1)
    Persistent daemon, dial-in runtimes, and runtime capabilities Implemented; capability attachments, dial-in runtimes (the TUI embeds one when remote), listening daemon with TLS, directory-independent daemon; landed in the pre-1.0 client protocol 45 and runtime protocol 5; manual labpc check (ssh template and dial-in) passed 2026-10-20
    Live engine configuration Implemented; config.get/config.apply/config.reload (pre-1.0 client protocol 48), live reload of settings, agents, providers, headers, and MCP servers, TUI /config and cookie config, plus provider-connect fixes; addendum (2026-10-23) implemented: clients restart the daemon (daemon.restart, client protocol 1.19.0)
    Compatibility v1 Implemented; client, plugin, and runtime protocols frozen at 1.0.0 with an enforced compatibility checker, tolerant session history (format 1) with conversion, golden logs and frozen corpora, user media input, and structured tool display
    Plugins: tools, hooks, events, and producers Implemented; plugin tools over the runtime tool messages, plugin protocol 1 on the runtime stack, plugins.list/plugins.restart, landed in the pre-1.0 client protocol 44
    External producers Implemented; named producers for plugins and runtimes under one external { source, name } owner
    Goal mode and producers Implemented, approved product contract
    Subagent handles Implemented (2026-09-17); short tree-unique handles for model-facing session references, with the later tool changes the status line lists
    Agent messaging Implemented; governing contract for send_message agent-to-agent messaging
    Tree-scoped session ownership lock Implemented; one owner.lock per root session tree, no lock files for delegated children
    Tree-local sessions Implemented; tree isolation for all session state, metadata-only listing, no cross-session usage rollups
    Store lock retention Implemented; bounded acquisition, commit-time CAS, lock-free OAuth reads, and per-run daemon token for ~/.cookie-agent secure stores
    Tool output streams and artifact reads Implemented; correctness and performance/code-quality reviews passed

    Drafts and records¶

    Drafts and preserved proposals, and records of finished refactors.

    Specification Status
    Full tool headers on open rows Approved draft (2026-10-29), decisions made; a client-only change in which an open tool row's header wraps to show its whole title and primary argument, with the status kept on the first line, while a folded row stays one cut line with no tooltip; ACP arguments keep their 200-character first-line cut
    Reduced transcript display Approved draft (2026-10-29), decisions made; a client-only reduced transcript mode, the default in both clients, that folds each assistant block's thinking, tool calls, and text between them into one Working… 42s row (subtext: the newest thinking line or tool title) and then Worked for 1m 23s · 7 tool calls above the reply; set in tui.toml, which /transcript and Ctrl+O write, and per browser in the web's new Settings › Display, which also takes Diagnostics in the transcript from This browser
    Managing runtimes from clients In progress (2026-10-26), decisions made, phase 1 implemented (client protocol 1.36.0, runtime protocol 1.9.0: each MCP server's tools by their own names, and the tools and ACP agents of each runtime in both machines views); per-runtime MCP servers and ACP agents in the daemon's configuration applied live, the machines panel's server, tool, and agent editors, every-runtime profiles, restarting template and dial-in runtimes, and MCP OAuth for servers on any runtime
