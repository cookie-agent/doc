Module display_view 

Source
Expand description

The display view of a session’s history and its newest-first windows (docs/site/specs/session-storage-v3.md section 3, client protocol 1.59.0).

The display view is what a transcript shows of a session’s events:

  • Bookkeeping is left out: model_request_prepared, which no client reads, and a model_replay_evaluated whose decisions discard nothing (its rows are below the warning level).
  • Superseded settings are left out of a page: a model_tools_published a later one in the page replaces, and in an acp_session_updated a command list or starting options a later one replaces, or a tool presentation a later one of the same call replaces. An update left empty is dropped.
  • Long tool results are cut: a result whose output, display, and metadata take more than CUT_ABOVE_BYTES keeps the first CUT_KEEP_BYTES of its output, a display fit to the same budget, and no metadata; a CutOutput names it and the whole result’s size, and event.read returns it whole.
  • A tool result’s metadata is left out: no transcript reads it, and an ACP agent’s results repeat their whole output there.

Every other event is sent as stored. model_attempt_started, model_output_started, and model_usage_recorded stay: a transcript builds its replies, their thinking times, and their costs from them.

A newest-first window (tail_window) holds the newest display events within a byte budget starting at a run, the events before it its state depends on (state_events), and, when the newest run alone exceeds the budget, the run’s start, a HistoryGap, and its newest model attempts. older_page reads the history before a window the same way.

Constants§

CUT_ABOVE_BYTES
A tool result larger than this, output, display, and metadata together, is cut in the display view.
CUT_KEEP_BYTES
How much of a cut result’s output, and of its display, the view keeps.
