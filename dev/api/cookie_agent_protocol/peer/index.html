Module peer 

Source
Expand description

A symmetric JSON-RPC 2.0 peer for the runtime protocol and the plugin protocol.

Both ends of the runtime protocol send requests and notifications, so one Peer type serves the daemon’s client and the runtime’s server. It runs over any frame Transport: an in-memory pair, or LineTransport over a child’s stdio. Every frame is bounded by MAX_FRAME_BYTES. The envelope is information: members JSON-RPC does not define are ignored, and a request ID may be an integer or a string (this peer sends integers). A frame that is not JSON, or not a request, notification, or reply, ends the connection.

The transport’s recv must be cancel-safe: the peer’s I/O task selects between receiving and sending. When the connection ends, for whatever reason, the peer closes the transport (Transport::close) before it reports the connection ended, within CLOSE_GRACE.

The peer notes when a frame last arrived (Peer::last_heard), so an end can tell a quiet connection from a dead one, and Peer::close_with ends one found dead at once, even while a frame is stuck being sent.
