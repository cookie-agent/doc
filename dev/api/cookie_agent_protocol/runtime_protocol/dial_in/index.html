cookie_agent_protocol::runtime_protocol

Module dial_in 

Source
Expand description

How the daemon refuses a runtime that dials in on /runtime?id=<runtime ID>, since protocol 1.2.0. A refusal before the WebSocket upgrade is an HTTP status whose body is the reason in plain text; one after it is a close frame whose reason is the reason. A runtime stops dialing in on a permanent refusal and dials in again, after a wait, on any other.

Constants§

CLOSE_INITIALIZE_FAILED
Close code 1011: the runtime did not complete runtime/initialize, such as one of an incompatible version or one that did not answer in time. Transient.
CLOSE_NORMAL
Close code 1000, normal closure: the end that closes is done with the connection, such as a runtime that stops.
STATUS_CONNECTED
HTTP 409: a runtime is connected, or being accepted, under the ID. Transient: the daemon may not have noticed yet that an earlier connection of the same runtime ended.
STATUS_FORBIDDEN
HTTP 403: the runtime ID is reserved (global, local) or configured on the daemon, or the request carries an Origin header. Permanent.
STATUS_INVALID_ID
HTTP 400: the runtime ID is malformed. Permanent.
STATUS_UNAUTHORIZED
HTTP 401: the bearer token is missing or wrong. Permanent.
