The program to hand std::process::Command (or tokio’s) for a user-configured command: MCP stdio servers, ACP agents, runtime launch commands, and plugins all go through here. env is the child’s configured environment; a PATH in it is searched instead of the daemon’s, as Command itself does.

On Windows, Command appends only .exe to a bare name, so npx, which npm installs as npx.cmd, is “program not found”. A program with no path separator that does not already end in a PATHEXT extension is therefore looked up on PATH with each PATHEXT extension, as search_path_candidates does, and the first hit CreateProcess can start (.com, .exe, .bat, .cmd; never .ps1) replaces it. A .bat or .cmd hit goes to Command as is: since Rust 1.77.2 (CVE-2024-24576, “BatBadBut”) the standard library runs a batch file through cmd.exe /e:ON /v:OFF /d /c with escaping that keeps every argument literal, and fails the spawn when an argument cannot be passed safely. Never build that cmd.exe /c line by hand.

Elsewhere, and when nothing is found, program comes back unchanged.
