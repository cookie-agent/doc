Cross-platform per-user path resolution for Cookie Agent.

This module lives in cookie_agent_protocol because models, config, engine, server, TUI, and tools already depend on that low-level crate. Placing it in cookie_agent_config would create a dependency cycle with models.

canonical_home_dir
Returns the current user’s home directory canonicalized, as a runtime reports it (home of runtime/initialize): see canonicalize. The home as home_dir gives it when it cannot be canonicalized.
canonicalize
path canonicalized for showing and comparing: on Windows without the \\?\ verbatim prefix std::fs::canonicalize adds, whenever the path means the same without it (see simplified); elsewhere exactly what canonicalize returns. Every canonical path a person or a model reads, such as a workspace root or a session’s directory, comes from here, so they all compare equal.
home_dir
Returns the current user’s home directory.
host_name
This machine’s host name; empty when it is unavailable.
machine_id
A stable, opaque identity of this machine, so a client can tell whether a daemon runs on its own machine: a SHA-256 of the operating system’s machine ID (/etc/machine-id or /var/lib/dbus/machine-id) or, where there is none, of a random ID kept in ~/.cookie-agent/machine-id, created on first use. The fallback is per user, so two users of one machine without an OS machine ID look like two machines. None when neither is available.
resolve_program
The program to hand std::process::Command (or tokio’s) for a user-configured command: MCP stdio servers, ACP agents, runtime launch commands, and plugins all go through here. env is the child’s configured environment; a PATH in it is searched instead of the daemon’s, as Command itself does.
search_path_candidates
Pure candidate selection behind where.exe-style lookups: for each PATH entry in order, tries name with each PATHEXT extension in order (default .COM;.EXE;.BAT;.CMD). Like where, a name that already ends in a PATHEXT extension (case-insensitive) is tried as written instead. Entries are ;-separated, may be double-quoted, and empty ones are skipped. No filtering happens here; callers vet the candidates.
simplified
path without the Windows verbatim prefix (\\?\C:\… becomes C:\…, \\?\UNC\server\share\… becomes \\server\share\…) when the path means the same without it: shorter than MAX_PATH, and with no component a non-verbatim path would read differently (a device name such as CON, or a name ending in a dot or a space). Other paths, and every path on other platforms, are returned unchanged.
user_data_root
Returns the unified Cookie Agent per-user data root.
