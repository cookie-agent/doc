Module errors 

Source
Expand description

The error registry, as specified in docs/site/specs/compatibility-v1.md section 6: every error the four protocols send carries a stable data.code and a message a user can understand, both from this one table.

An error object is built from its registry entry:

use cookie_agent_protocol::errors;

let error = errors::MEDIA_UNSUPPORTED
    .error()
    .field("kind", "image")
    .field("model", "anthropic/claude-haiku-5-5")
    .detail("the model declares input modalities: text")
    .try_build()
    .unwrap();
assert_eq!(error.code, errors::APPLICATION_ERROR);
assert_eq!(error.message, "The model anthropic/claude-haiku-5-5 does not accept image input.");
assert_eq!(error.data.unwrap()["code"], "media_unsupported");

Clients branch only on data.code, show message, then hint when present, and detail on request. Nothing sends these errors yet; the daemon, the SDK, and the runtimes switch to them in later phases.
