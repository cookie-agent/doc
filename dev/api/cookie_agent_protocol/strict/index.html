Strict decoding of commands (docs/site/specs/compatibility-v1.md section 4.1).

Information types ignore members they do not know, so a type that is also part of a command (a crate::RunSelection in run.start, a crate::PermissionRule in session.create) cannot reject them itself. A command’s receiver therefore checks the params against the command’s published JSON Schema first: every member of an object must be one of the properties the schema lists for it, and every enum value or tag one the schema lists, wherever it is in the params. Serde then decodes the params as usual. Open enums are no exception: a command never carries a value its receiver does not know, since its sender gates new values on the receiver’s version.

check_command
Checks value against a command’s schema: the first member the schema does not list, or enum value it does not list, is refused with its JSON path. Members are checked only where the schema lists properties; a free-form object (one that lists none) takes any.

Decodes value as the params of a command of type T, refusing any member or enum value T’s schema does not list.
