Cookie Agent’s MCP client: the servers one runtime hosts, as a ToolProvider.

An McpRegistry connects every enabled server eagerly, lists its tools as <server>_<tool>, marks their descriptions and results as untrusted server output, retains result media as attachments, and follows each server through its states (McpServerState). A connected server that drops is reconnected with the shared ReconnectPolicy: its tools stay published and calls fail fast with runtime_unavailable meanwhile, and when every attempt fails its tools are dropped and the failure is broadcast (docs/site/specs/runtimes.md section 6.4). Names are unique inside one registry: a server whose generated name collides with a reserved name (the hosting runtime’s other tools) or with another server’s tool fails.

The daemon’s global runtime hosts the top-level [mcp] servers with one registry, and each coding runtime hosts its template’s servers with another. OAuth for remote servers, with its credential store, exists only with the oauth feature, which only the daemon enables; a registry opened without a credential store connects every server without OAuth.
