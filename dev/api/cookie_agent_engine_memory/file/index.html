The memory file format (docs/site/specs/memory.md section 4.3, with the stamps of section 16.9.6) and revisions (section 4.4).

A memory file is YAML frontmatter between --- lines, with a required description, optional keywords, and the created and modified stamps the daemon sets, followed by a Markdown body that may be empty. Parsing is strict: an unknown key, a wrong type, a stamp that is not a timestamp, a frontmatter that does not parse, or a file larger than any memory may be (MAX_FILE_BYTES) makes the file invalid, with a reason. A file over its kind’s [memory] limit is still valid; writes enforce the limits (section 16.9.7). Control characters other than newline and tab make a file invalid too (section 13); \r\n line endings are read as \n.
