Brings the agent files in line with desired, the agents the daemon keeps a file for, which is asked for once the memory lock is held so that the latest registries win a race between two syncs. Makes sure project’s overview exists and carries the daemon’s description: a missing file is created with an empty body, and a valid file with another description has its frontmatter rewritten, its keywords and body kept. pub fn write( &self, url: &MemoryUrl, text: &str, mode: WriteMode<'_>, owners: impl MemoryOwners, limits: &MemoryLimits, now: Timestamp, ) -> Result<Written, StoreError>

Creates or replaces one memory from its whole file text, which must be a valid memory. mode says how the memory it replaces is checked (WriteMode). The daemon stamps the file (section 16.9.6): a new memory is created now, a replaced one keeps when it was created, and either is modified now; stamps the text gives are ignored. The result must fit the memory’s limit in limits, unless the memory is already over it and the write makes it smaller (section 16.9.7). Creating an agent:// file needs owners to know its agent. An agent:// file keeps the frontmatter the daemon owns (section 16.7): the daemon’s description and keywords for an agent it keeps a file for, and the description the file has otherwise; a project’s overview keeps the daemon’s description the same way. The body is kept as given and the frontmatter rendered anew. A write to a project that does not exist is refused; the first memory of a machine creates its folder.

Source

pub fn edit( &self, url: &MemoryUrl, old: &str, new: &str, owners: impl MemoryOwners, limits: &MemoryLimits, now: Timestamp, ) -> Result<Edited, StoreError>

Replaces the one occurrence of old in the body of a memory with new, whatever else changed in it since the caller saw it (section 16.9.8). Fails, changing nothing, when old occurs zero or several times, the result is not a valid memory, or it does not fit the memory’s limit (MemoryRoot::write). The file is written in the form MemoryDocument::render gives, stamped as modified now, with the daemon’s description and keywords for an agent file the daemon keeps (section 16.7).

Source

pub fn check_edit(&self, url: &MemoryUrl, old: &str) -> Result<(), StoreError>

Whether an edit of the memory at url replacing old would apply now: the memory exists, is valid, and old occurs once in its body. Changes nothing; the edit checks again when it runs (MemoryRoot::edit).

Source

pub fn delete( &self, url: &MemoryUrl, expected: Option<&MemoryRevision>, ) -> Result<String, StoreError>

Deletes a memory, at revision expected when one is given (a client’s delete), and returns the text it held. A model’s delete deletes, whatever the layer (section 16.9.11). A project’s folder stays when its last memory goes: it belongs to the project.

Source

pub fn stamp_unstamped(&self) -> Result<usize, MemoryError>

Stamps every valid memory file without stamps with its modification time, as created and modified (section 16.9.6), adding only the missing lines before the frontmatter’s closing ---, so the rest of the file stays as written. Run once at start; until a file is stamped, reads take its modification time instead. Returns how many files it stamped, and signals when it stamped any.

pub fn create_defaults_if_absent(&self) -> Result<bool, MemoryError>

The first start of section 4.5: when the memory folder does not exist, creates it with the four layer folders and the default user categories, and returns true. A memory folder that exists, whatever it holds, is never touched.

The folder is built under a temporary name in the data root and renamed into place, so a crash leaves no half-made memory folder that later starts would take as the user’s, and a second daemon starting at the same moment keeps the first one’s folder.

pub fn lock(&self) -> Result<MemoryLock, MemoryError>

Takes the advisory lock on memory/.lock, waiting a few seconds for another process. While the memory folder does not exist there is nothing a change could race with, and the lock creates nothing, so that the first start still finds no memory folder: the returned lock then holds no file.
