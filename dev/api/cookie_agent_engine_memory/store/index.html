Module store 

Source
Expand description

Reading, listing, and changing memory files (docs/site/specs/memory.md sections 4 and 8, as section 16.9 amends them: stamps, size limits per kind of memory, model writes without revisions, and the similar-memory check).

Reads never take the lock: every write replaces a file by renaming a flushed temporary file over it, so a reader sees the old or the new file whole. On Windows that rename can leave the name briefly unresolvable, so reads go through secure_store::read_replaced and its kin. Writes, edits, and deletes take super::MemoryLock for their whole check-and-change, and may wait for it up to a few seconds, so async callers run them on a blocking thread.
