Permission evaluation over immutable prepared-operation manifests.

Modules§

identity
The approval identity of a call a provider only declares: a runtime’s or a plugin’s tool, or an MCP server’s. The provider states the call’s permission, resource, and normalized arguments; the daemon binds them to the tool it knows the call goes to (docs/site/specs/compatibility-v1.md section 9.4), so a peer can never state another tool’s identity, and no peer has to reproduce a digest byte for byte.

MergedRules
A run’s permissions as one rule list (docs/site/specs/permission-consolidation.md section 3): the frozen policy’s rules (the agent document’s, and the defaults of each action it names no key for), then the session overlay’s. An overlay rule replaces every policy rule with its identity (action, runtime selector, and pattern, a leading ~ expanded against the scope’s home as matching expands it); every other overlay rule is added. Functions§

agent_permission_rules
The rules an agent document gives its runs: the document’s own, then the mode defaults of each action the document names no key for, with or without a runtime selector, and the memory defaults (memory_default_rules) and the cron default for a root or delegated run likewise. A declared key replaces its action’s default entirely. The memory rule variables are expanded with variables as the run’s policy is frozen, so frozen rules, which the wire carries, never hold one.
agent_rules_with_sources
The rules a root or delegated run of document’s agent starts with, as agent_permission_rules gives them before the memory variables are expanded, each with whether the daemon supplied it as a default.
attach_default_rules
The attach default (docs/site/specs/machines-on-demand.md section 3.3): a root run may attach and detach machines, and a delegated one, or an internal agent, has no rule, so the tools are hidden.
check_rule_selectors
Refuses overlay rules a client sends with a runtime selector their action takes none of (message@labpc), as agent documents do. Only commands are checked: an overlay already in a session log reads as it is.
cron_default_rules
The rules a run of an agent of mode gets for cron when its agent document names no cron key (docs/site/specs/cron.md section 7): a root run of a non-internal agent manages every job; a delegated run and an internal agent get nothing, so the cron tools are hidden unless granted.
effective_permission_view
The effective permission of every action, as the merged list of policy and overlay (MergedRules) gives it: the built-in actions, then the other actions the session’s tools declared, then any other action a rule names, each group in first-seen order. Each action reports its last unqualified * rule as its effect (ask, what no rule matching gives, with the source default without one) and lists every other rule as a pattern, each with its source; an action whose policy rules are exactly its mode default, or its memory default (memory_default_rules) for a root or delegated run, reports them with the source default. A session * rule replaces only the * row: the document’s other patterns stay listed, because they still apply.
effective_permission_with_overlay
The effect of action on resource in scope under the merged list of policy and overlay (MergedRules::decide).
expand_home_pattern
pattern with a leading ~ (the whole pattern, or ~/ before the rest) replaced by home, the home directory the tool’s runtime reported, spelled with / as path labels are. Without a home, and for any other pattern (~user/… included), pattern as it is: a literal ~ then matches no absolute path. Pure and allocation-free when nothing expands.
governing_agent
The agent of the latest visible run, else the session’s creation agent.
governing_agent_for_skills
message_default_rules
The message rule a run of an agent of mode gets when its document names no message key: a delegated run messages anyone in its tree; a root run follows its delegate rules (delegate, the run’s own or the default), allowed when one of them allows, asking when one asks, and denied when it may delegate to nobody, as it then has no subagent to message. Internal agents get nothing.
mode_default_rules
The rules the daemon supplies for an agent of mode (docs/site/specs/runtime-delegation.md section 4 and docs/site/specs/runtimes.md section 7.1), each applying only to an action its document names no key for. Every agent but an internal one reads every file, edits files in its workspace and asks for any other path, fetches the web, uses every skill, calls MCP tools after asking, and delegates to nobody; primary and all agents also list runtimes. Internal agents, which call no tools, are denied every action. Memory’s defaults depend on whether the run is delegated, so they are separate (memory_default_rules), and message follows delegate (message_default_rules).
patterns_intersect
Whether some resource matches both left and right, wildcard patterns of * (any characters) and ? (one character). Decided exactly, without any resource having to exist; a trailing *, which also matches the bare prefix, counts both ways.
rule_effects
The effect of action on resource in each of scopes. A ~ in resource, a rule’s pattern, expands against each scope’s home as the rule’s own pattern does.
run_default_rules
Every rule the daemon supplies to a run of an agent of mode, root or delegated, each for an action its document names no key for. Whatever no rule matches asks (MergedRules).
run_default_rules_with_delegate
run_default_rules for a run whose delegate rules are delegate: the message default follows them.
stricter
Whether any scope’s effect got stricter between old and new.
tool_visible
Visibility is action-level opt-in, not a resource authorization decision: whether the merged list of rules (a frozen policy) and overlay offers action to a tool of the runtime with ID runtime (None for the base layer), as the run’s merged rule list decides it.
