Expand description

The approval identity of a declared call of tool, prepared under origin_context (its origin’s cookie_agent_runtime_api::ToolOrigin::context_bytes):

  • its normalized arguments’ digest, over their canonical JSON (object members in key order);
  • one capability, permission (or tool for a tool that needs none), operation <tool name>:call;
  • one resource of that action: canonical <action>:<SHA-256 of the resource> (<action>:unscoped without one), bound to the tool’s identity and the resource. A shell command approves by command prefix, anything else exactly. A command’s or a path’s binding is process-local, since the runtime resolves it against its own machine’s state at preparation; every other binding is restart-stable, the tool’s identity and the resource being all it names;
  • the execution context: the tool’s identity and its origin’s context.

The tool’s identity is the source the daemon resolved (the runtime attachment, plugin, or MCP server) and the name the source knows the tool by, never anything the provider reports.
