The contract between Cookie Agent’s engine and the tools it runs.

A tool provider implements ToolProvider: it declares ToolSpecs, prepares calls into PreparedTools, and executes them with a ToolExecutionContext. Everything a provider needs lives here, so tool crates depend on this crate and the protocol types, never on the engine.

The engine provides the host services a call uses through traits defined here: ProgressCapture (output capture), ToolArtifacts (artifact retention and reads), and a DetachPoint through which a background-capable tool says when the host may detach it. The runtime identity types (ToolOrigin, RuntimeInfo, WorkspaceContext) say which runtime a tool belongs to, as specified in docs/site/specs/runtimes.md.

protocol holds the wire types of the runtime protocol that connects the daemon to a runtime in another task or process, and rpc the JSON-RPC peer both ends run.
