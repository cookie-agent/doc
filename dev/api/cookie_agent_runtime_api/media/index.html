sniff_media_type
Recognizes a media file from its first MEDIA_SNIFF_BYTES (or all of it, when shorter) and its total length, so size limits apply before the whole file is read. A recognized file still needs approved_media_type.
tool_input_media
The media a model accepts from a tool: every kind of capabilities that family can deliver, with the lower of the model’s and the family’s byte limit, and how it is delivered.
user_input_media
The media a model of capabilities behind family accepts in a user turn: what clients are told it accepts and what input is admitted by (docs/site/specs/compatibility-v1.md section 11.2). User content always travels in a user turn, so every kind family can deliver at all counts, unlike in tool_input_media. The media types are those of the model’s that an upload can be recognized as; the byte limit is the lowest of the model’s, the family’s, and the attachment cap; images also carry the dimension and pixel limits validation applies. A kind left with no media type is left out.
validate_attachment
Checks that bytes are a supported media file of the declared mime_type within the attachment size bounds.
validate_upload
Recognizes and validates an upload: its media type comes from its content alone, never from a filename, and it is held to the checks and caps a tool attachment is (the runtime’s validate_attachment), with an image’s size reported.
