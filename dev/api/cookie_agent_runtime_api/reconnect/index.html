How a dropped connection is bridged (docs/site/specs/runtimes.md section 6.4).

The same policy applies to MCP servers (in the daemon’s global runtime and in coding runtimes) and to runtime instances: when a connected one drops, its host reconnects it (restarting the process for stdio servers and runtimes) a bounded number of times with growing backoff. While it reconnects its tools stay published and calls fail fast with runtime_unavailable, so a brief drop never changes the tool list. When every attempt fails, the caller drops the tools and reports the failure to clients.

ReconnectPolicy::run owns only the attempt loop; the caller supplies one connection attempt and decides what the outcome means for its state.
