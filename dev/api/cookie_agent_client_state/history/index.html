Module history

Expand description

A session’s history as the display view holds it (client protocol 1.59.0, docs/site/specs/session-storage-v3.md section 3).

A client that asks for the display view opens a session at its newest messages: the daemon answers with the newest runs, the header events the session’s state depends on, and what it left out (older history, and a gap inside a run larger than its budget). The store keeps those events, the live events after them in the display view, and the live-only output still in flight, and folds them again whenever older history arrives or a cut tool result is read whole: the display events are small, so a fold is cheaper than a reducer that can prepend.

The fold starts from the header: its events are reduced into a scratch projection whose latest-wins state (agent, model, ACP settings, tools, goal, attachments, hold, queued inputs) seeds the projection the held events then reduce onto, so no row of an older event shows and no older setting overrides a newer one.
