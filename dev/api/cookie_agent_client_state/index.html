Crate cookie_agent_client_state 

Source
Expand description

The client state every Cookie Agent client shares: disposable projections reduced from the protocol’s stored and transient events, independent of how a client renders them. The TUI and the web client both keep a StateStore; it builds for wasm32-unknown-unknown too.

Assistant attribution is derived only from the frozen RunStarted plus ModelAttemptStarted/ModelTurnCommitted ownership — never from the current picker, live agent files, or provider configuration. The visible assistant header projects the canonical Agent • Model[variant], with the model’s display name (looked up at render time) ahead of its id.

Where a session runs, as the badges a session row shows (docs/site/specs/projects.md section 9), and the stable colour of a machine. Badges show machines, never runtime IDs, and the global attachment never counts. A session with no other attachment has no badge; one machine shows its badge and the workspaces, as ~/…; several machines show each machine, in attachment order. A root’s badges count its own attachments followed by the ones its subagents brought (SessionMeta::delegated_attachments, client protocol 1.10.0; docs/site/specs/runtime-delegation.md section 5.3). The machine comes from runtimes.list; a runtime of no known machine stands for its own machine, under its runtime ID. Under a project’s header, a machine its defaults name shows as its icon alone, and the workspaces leave the row when its defaults name them all: the header already says both.
