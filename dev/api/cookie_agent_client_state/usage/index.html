Module usage 

Source
Expand description

Usage figures every client shows the same way: token counts with thousands separators or in short form, costs, and the prompt-cache hit rate of a session, a session tree, or one model of either (session.usage, session.tree_usage).

The hit rate is the share of the prompt the provider read from its cache:

hit rate = cache-read input tokens ÷ inclusive input tokens

where inclusive input counts every prompt token: the uncached ones plus the cache reads and the cache writes. Adapters report input_tokens inclusive (it is never summed from its parts), so input_tokens already contains cache_read_tokens and cache_write_tokens. The daemon computes the rate (cache_hit_rate) over the requests whose provider reported cache reads, so a request that said nothing about the cache does not count as a miss; a client shows that rate as it comes and never recomputes it from the totals, which include such requests.
