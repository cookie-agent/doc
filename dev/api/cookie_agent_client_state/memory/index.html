Module memory 

Source
Expand description

The /memory panel’s rules every client shares: the memories as rows by layer and group, what a new memory starts from and where, what memory.write answered, how a delete’s refusal reads, the parts of an agent:// file the daemon owns, and a memory’s stamps and size limit, which the daemon owns too (memory spec sections 16.9.6 and 16.9.7).

Structs§

AgentMemoryParts
An agent:// file as an editor shows it: the daemon owns its description and its first keywords (the agent’s ID, then its mode) and keeps them whatever a write gives; the other keywords and the body are the user’s.
MemoryStamps
A memory’s stamps and size as memory.list or memory.read report them; each is absent from a daemon older than client protocol 1.14.0.
MemoryTime
One of a memory’s times, for a line of its own.

MEMORY_STAMPS_MINOR
The client protocol minor from which a daemon stamps every memory with created and modified, reports them with last_read and the size limits in memory.list and memory.read, and owns the stamp lines of a memory’s frontmatter, rewriting them on every save.

OVER_LIMIT_NOTE

without_stamps
text without the stamp lines of its frontmatter (created: and modified: at the top level), the rest kept byte for byte. The daemon writes its own stamps on every save whatever the text says, so an editor shows the text without them and saves it as it is left. A text without frontmatter is returned whole.
