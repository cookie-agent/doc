Module cut_points 

Source
Expand description

Where a client’s revert and fork cut a session’s history: before a user message, at the end of a reply, and before a compaction. The daemon cuts at any sequence (session.revert, session.fork); these are the points the transcript offers.

A cut before a user message keeps the reply before it: the daemon leaves out the run the message starts along with it. So reverting or forking at a user message keeps what a cut at the end of the reply before it keeps, apart from the settings changed in between, and the message’s text goes back to a composer.
