Incoming webhooks (docs/site/specs/webhooks.md).

The request side, as pure functions over a request the HTTP layer has read: request (the request, its body, delivery IDs, and values a filter or a thread key reads), verify (the signature checks of section 6), filter (section 5.2), render (the <webhook_event> message of section 7.1), and ids (webhook IDs and URL tokens). They live in the engine because delivery is the engine’s; the daemon’s HTTP route reaches them through it.

filter
A webhook’s filter (docs/site/specs/webhooks.md section 5.2): every condition must hold for a request to become an event.

Webhook IDs and URL tokens (docs/site/specs/webhooks.md section 4).
render
The message an event reaches the model as (docs/site/specs/webhooks.md section 7.1): marked as a webhook event, never as the user, with the request as untrusted data.
request
A webhook request as the HTTP layer read it, its body, and the values a filter or a thread key reads (docs/site/specs/webhooks.md sections 5.2, 5.3, 7.1, and 7.4).
verify
The signature checks a webhook may add to its URL token (docs/site/specs/webhooks.md section 6). Every comparison is constant time.
