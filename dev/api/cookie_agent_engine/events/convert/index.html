History format conversion (docs/site/specs/compatibility-v1.md section 8.7).

A log written under an older history format is converted to HISTORY_FORMAT when a newer build opens it. Each step is a function from the old log’s JSON lines to the next format’s lines, in v<N>_to_v<N+1>.rs, registered in CONVERTERS and kept, so the steps chain: a format-1 log opened by a format-3 build converts 1 to 2 to 3. Converters never use old Rust types; they read and write JSON. A step may move values out of the log into the tree’s blobs (Blobs, by digest): the caller writes them to blobs/ before the converted log (convert_tree), or keeps them in memory for a read-only open.

A log without a history_format predates history formats and is not converted.

§Adding a converter

When a change cannot follow the additive rules of section 8.4, the history format bumps from N to N + 1 and this module gains v<N>_to_v<N+1>.rs, as v1_to_v2.rs did for format 2:

  1. Bump HISTORY_FORMAT in cookie_agent_protocol.
  2. Write pub(super) fn convert(lines: Vec<Value>, blobs: &mut Blobs) -> Result<Vec<Value>, String> in v<N>_to_v<N+1>.rs: it reads format-N lines as JSON (envelopes and payloads exactly as a format-N writer stored them, the storage encodings included, such as a tool result’s display_span, text_span, and lines_span, and format 2’s blob references) and returns format-N + 1 lines. It names no Rust event type, since those are the newest format’s; a line it does not understand (an unknown or newer record) is copied unchanged. The chain stamps the new history_format on session_created afterwards.
  3. Declare the module and register Converter { from: N, convert } in CONVERTERS. Converters are never removed.
  4. Record new golden trees in crates/engine/tests/fixtures/history/<N + 1>/ with the golden recorder, beside the older formats’ trees, which stay frozen: their test then opens each older tree through the converters and compares the result with the snapshot it was recorded with, wherever the new format does not change what the snapshot shows (where it does, the test compares the converted tree with what the new format defines instead).
  5. Describe the format in docs/site/reference/events.md (History formats) and the converter in the compatibility spec’s notes.

The test-only step from format 0 (TEST_CONVERTERS) exercises the chain, the tree conversion, and the backups apart from any real format.

Converts the complete lines of a log in from to HISTORY_FORMAT and returns the new log’s bytes, with the blobs it names that the conversion moved values to. A line that is not JSON is left out; the original keeps it.

Whether a log in format can be converted to this build’s.
