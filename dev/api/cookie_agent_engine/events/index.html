What a native model’s context is assembled from: the records since the window’s start, and the records before it that what follows still names (docs/site/specs/forever-sessions.md section 5.1).
state
What a log’s readers need of all its events, kept up to date as it grows (docs/site/specs/forever-sessions.md, sections 3.1, 3.2, and 3.4): opening a log folds it once, an append folds one event, and a revert folds what stays again. A reader takes EventLog::state rather than passing over the list.

state.json: what a windowed log’s records fold to, saved beside it, so that an open reads only what comes after (docs/site/specs/forever-sessions.md section 4).

The records of the event file at path from byte offset on, through its last complete line, each read as the loader reads an intact record: its values history format 2 keeps in the tree’s blobs/ read back (blobs::internalize), then typed as it is (StoredEvent::decode_strict). syncs_on_append
Whether a record is a commit point, synced before it takes effect: before its append returns and before it is published (docs/site/specs/store-locks-and-durability.md, section 3). What something outside the log acts on is one: a tool call’s start (before the tool runs) and end (before the next model request), what a request’s reply confirms, grants and approval decisions, delegation records, session creation, a run’s end, and every rare kind, whose sync costs nothing. The rest rides along: written at once, synced by the next commit point or when the log closes, so a crash can drop only such records after the last commit point. Live-only kinds are never appended.
