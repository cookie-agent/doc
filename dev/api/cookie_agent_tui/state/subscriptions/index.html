Module subscriptions 

Source
Expand description

Which sessions a client keeps subscribed, and when it tries again.

A session with a live tail cannot be evicted by the daemon, so a client that browses many sessions keeps only the trees it viewed most recently subscribed (RECENT_SUBSCRIBED_TREES) and releases the settled sessions of the others: a session with a run, or with input whose start or return the view must still see, is released once it settles. The client owns the clock and the requests; this only decides.

Subscriptions is the per-connection state machine of every session’s events.subscribe. Every subscribe costs a paged history replay, a staged rebuild in the view, and a replacement of the connection’s live tail, so a session is subscribed at most once while that subscription is healthy. Whether a finished subscription is live depends on ownership, which the client classifies: the daemon answers a session it does not own with a read-only snapshot and registers no tail. The protocol client owns cursors and replay staging and runs recovery replays on its own; this machine only tracks them. Its methods return the Subscribe requests the client must send, and the client reports how each ended.
