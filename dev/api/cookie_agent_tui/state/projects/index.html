Module projects

Expand description

Projects in the clients (docs/site/specs/projects.md section 10): the session list’s project sections, the project pickers, the emoji check the daemon makes, and what choosing a project does to a new-session draft: its default attachments and its default agent and preset.

Structs§

ProjectSection
One section of the session list: a project’s root sessions, or (with no project) those of no project. S is how it holds them: owned, or borrowed from the list (project_sections_borrowed).

Functions§

daemon_has_projects
Whether a daemon whose handshake reported version keeps projects. Before the handshake nothing is known.
defaults_attach
Whether a new session in a project with defaults takes their attachments: they name runtimes or leave out global, as the daemon decides. Defaults that only name an agent or a preset leave the usual attachments.
defaults_requests
The attachments defaults name: whether global is attached, and the other runtimes as session.create takes them, in order.
delete_question
The question a project’s delete asks, with what goes.
editor_defaults
The defaults a project editor saves: the attachments (global and the other runtimes, a runtime listed twice kept once), the agent, and the preset. None when that is all the daemon’s usual defaults, so the project keeps none.
find_project
The project id names among projects; None for no ID and for a project that no longer exists, which lists as no project.
project_agent
The selection project’s default agent and preset give a new session (docs/site/specs/projects.md section 4): the agent among agents that runs as root in that preset (with no agent named, the preset’s default_agent, else its first), and that agent’s model: an ACP agent’s synthetic one, else its first live accepts, else fallback_model.
project_choices
The lines of a project picker filtered by query (case-insensitive, over the name and the emoji): the projects in projects’ order, “No project”, then “New project…” (offered whatever the query says, when creates).
project_label
A project as clients name it: its emoji, when it has one, then its name; NO_PROJECT for none.
project_sections
The session list as project sections. A section per project, oldest project first: project IDs are UUIDv7s, so their order is the order the projects were created in, and a new project goes last without moving the others. “No project” comes last and holds every root session of no project or of a project that no longer exists. Each section orders its sessions by order_sessions. Delegated sessions are left out.
project_sections_borrowed
project_sections, each section borrowing its sessions from sessions rather than copying them.
running_sessions
The sessions a refused delete names as running (project_sessions_running); empty for any other error.
running_sessions_message
What a client says when a delete was refused because running sessions run: their titles (else short IDs) from sessions.
section_key
The key of the section of project (None: no project).
validate_emoji
Checks emoji as the daemon does (docs/site/specs/projects.md section 3): one extended grapheme cluster of at most 32 bytes, holding a character Unicode marks as an emoji, made only of emoji characters and emoji components, and not ASCII, whitespace, or a control character. The error says why, for the field to show at once.
