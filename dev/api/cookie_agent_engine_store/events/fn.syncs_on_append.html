Whether a record is a commit point, synced before it takes effect: before its append returns and before it is published (docs/site/specs/store-locks-and-durability.md, section 3). What something outside the log acts on is one: a tool call’s start (before the tool runs) and end (before the next model request), what a request’s reply confirms, grants and approval decisions, delegation records, session creation, a run’s end, and every rare kind, whose sync costs nothing. The rest rides along: written at once, synced by the next commit point or when the log closes, so a crash can drop only such records after the last commit point. Live-only kinds are never appended.

No catch-all: a new kind does not build until it is put in a class.
