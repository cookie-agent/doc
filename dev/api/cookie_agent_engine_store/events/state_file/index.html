Module state_file 

Source
Expand description

state.json: what a windowed log’s records fold to, saved beside it, so that an open reads only what comes after (docs/site/specs/forever-sessions.md section 4).

The file names a record, the tip of the log when it was written, and holds what folds give as of that record, and where the window starts. It is a cache: it is written without a sync, and a missing, unreadable, or mismatched one means folding the log from its start, one record at a time and keeping only the window, so what that takes in memory does not depend on the log’s length. Only a log that is damaged, or of an older history format, reads the way it always has: whole, as quarantining a record needs.

It stays valid across builds. A change to what a fold gives leaves the file’s shape alone and its contents wrong, so it must raise STATE_VERSION, and a test holding a digest of what the folds give on the golden logs fails until that happens (section 4.4).

Constants§

STATE_FILE
The file beside a session’s events.jsonl.
STATE_MIN_LOG_BYTES
A log shorter than this has no STATE_FILE: folding it from its start takes a few milliseconds, and the file would be about as large as the log, or larger.
STATE_VERSION
What STATE_FILE’s contents mean. Raise it when what a fold gives changes, or the file’s shape does: a different one means folding the log from its start. The test the_folds_of_the_golden_logs_match_their_recorded_digest says when.
