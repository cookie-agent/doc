Module blobs 

Source
Expand description

History format 2’s blobs (docs/site/specs/session-storage-v3.md, section 4.2): the large values of a session log’s records live in the tree’s blobs/ folder, each named by the SHA-256 of its content, and the record names them by digest.

What moves out of a record:

  • a tool result’s output longer than OUTPUT_BLOB_MIN_BYTES: the record keeps its first OUTPUT_HEAD_BYTES (cut at a character boundary) as output, its byte length as output_bytes, and output_blob;
  • a tool result’s display and every part of its metadata whose JSON is longer than OUTPUT_BLOB_MIN_BYTES, each whole: an object of the metadata only once the large members inside it moved and it is still that long, and the metadata itself the same way. The result lists them in moved_values, each {"pointer", "value_blob"}, pointer a JSON pointer into the result (/display, /metadata/acp/raw_output), in the order they moved;
  • acp_session_updated’s commands and options, and run_started’s agent.fallback_chain and each internal agent’s fallbacks, whose JSON reaches VALUE_BLOB_MIN_BYTES: the member becomes <member>_blob, and the blob holds its JSON. Repeated lists are stored once.

A reference is the string artifact://sha256/<digest>, so artifact liveness (forks, reverts) sees blobs as it sees every other artifact: the folder is the one the tree’s artifacts live in.

Records in memory are whole: the loader reads every value back as it reads a line, and the writer moves them out as it writes one. So everything that reads a record (model replay, compaction, the approval reviewer, clients, plugins) gets the whole value.

An image an ACP tool returned is a file of the tree. Its copy in metadata.acp.raw_output is a reference to that file since history format 3 (reference_stored_images), which a reader that wants the base64 can encode again exactly.

Constants§

BLOBS_DIR
A tree’s blobs, beside its root’s log. It replaced artifacts/.
LEGACY_ARTIFACTS_DIR
Where a tree kept its artifacts before history format 2: a tree that was not converted yet (one another process holds) is read from there.
OUTPUT_BLOB_MIN_BYTES
A tool result’s output longer than this moves to a blob.
OUTPUT_HEAD_BYTES
How much of a moved output the record keeps.
STORED_IMAGE_MIN_BYTES
A string this long or longer may be the base64 of a stored file.
VALUE_BLOB_MIN_BYTES
A list whose JSON is at least this long moves to a blob; a shorter one is smaller than its reference would be worth.

Replaces each string at any depth of value that is entirely the canonical base64 of a file stored knows by digest with a reference to that file: whether it replaced any. Nothing is lost, as encoding the file again gives the string back (docs/site/specs/history-format-3.md).
sync
Syncs the blob at path, which a writer closed. The handle that syncs has write access, which Windows needs to flush a file, and is closed again at once, so it never keeps the blob or its folder from being deleted. A blob deleted meanwhile has nothing left to sync.
tree_blob_dir
The blobs/ folder of the tree the log at log belongs to: beside the root’s log, also for a child’s under subagents/.
write
Stores bytes as blob digest in dir, unless a blob of that length is there already, without syncing it. Returns the blob’s path when this call wrote it.
write_synced
Writes every blob of blobs to dir and syncs the ones it wrote, and the folder: a log that names them is synced after this.
