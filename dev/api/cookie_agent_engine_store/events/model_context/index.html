Module model_context

Expand description

What a native model’s context is assembled from: the records since the window’s start, and the records before it that what follows still names (docs/site/specs/forever-sessions.md section 5.1).

The window starts where the latest checkpoint’s kept range does. Before it, a log keeps only:

  • back-references: an applied input’s submission, a started call’s turn, an ended call’s start and its link to a child session, and, at any moment, the records of every call still open and every input not yet applied, so a record appended later names nothing the log let go of;
  • producer messages not yet consumed: each one’s acceptance and admission, and the acceptance of a message admitted in the window;
  • what assembly reads beside what it renders: the latest run’s run_started, which every record of the run names, its latest system_prompt_composed, the system prompt its requests carry, and the replay cut that reaches furthest;
  • under a checkpoint without context_fresh, which an earlier build wrote, every loaded skill and the latest AGENTS.md and memory records, as that build pinned them. A checkpoint with it recorded its own just before itself, in the window.

model_context applied to what it returned, with what was appended since, gives what it gives for the whole log: the log can let go of the rest, and a test of every log that asks for this checks it.
