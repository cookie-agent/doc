Restarting the daemon (docs/site/specs/engine-configuration.md section 11): cookie daemon restart, and how cookie daemon relaunches itself once a client asked it to.

The daemon remembers how it was started — its executable, arguments, environment, and directory — before it changes any of them. When a scheduled restart is due it shuts down as on a stop signal and then relaunches that command:

  • on Unix with an in-place exec, which keeps the process ID, so a service manager sees no change. Every descriptor the daemon opened is close-on-exec (Rust opens them so, and relaunch marks any other before the exec), so the new image starts with only standard input, output, and error, and binds the port the old one released;
  • on Windows by starting the same command line and exiting. The new process finds RESTARTED_ENV and retries binding its port for up to RESTART_BIND_WAIT while the old one exits.

The executable is the path the daemon resolved when it started, so a restart after an upgrade runs the new build.
