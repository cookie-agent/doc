dial_in 🔒
Dials in to the daemon at daemon as runtime id and serves it, connecting again after every drop or refusal for now with a growing wait, until stopped. A connection that has carried nothing, not even a pong to its keepalive pings, for DIAL_IN_DEAD_AFTER counts as a drop, so one that died without a close is noticed, and so does a connect that the daemon has not answered within CONNECT_TIMEOUT (a peer that takes the TCP connection and never upgrades it). A refusal for good, such as a configured or reserved ID or a wrong token, ends it with the daemon’s reason.
dial_in_id 🔒
Checks id as a runtime ID a runtime may dial in under: well formed and not a built-in runtime’s, which the daemon refuses.
host_runtime_id 🔒
A runtime ID for this machine: <prefix>_<host>, or the host name alone without a prefix, with the host name lowercased, every character outside [a-z0-9_] replaced by _, repeats and edges trimmed, at most 32 bytes. A bare host name that does not start with a letter gets host_ in front; no host name at all gives the prefix, or host.
run_runtime 🔒
cookie runtime serve --stdio: serves one coding runtime for the workspace over this process’s stdio until the daemon sends runtime/shutdown or closes standard input. Standard output carries only protocol messages; errors go to standard error.
warn_local_runtime_settings 🔒
Says once that this machine’s [runtimes.local] MCP servers and ACP agents, which only its own daemon’s built-in runtime hosts, are not the ones runtime id dials in with (docs/site/specs/runtime-management.md section 3.2).
