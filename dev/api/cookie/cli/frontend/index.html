Plain cookie and cookie attach: the TUI against a running daemon, or against one composed in this process.

Functions§

client_directory 🔒
This process’s canonical working directory, which the TUI sends as the directory of the sessions it creates; None when it is unavailable.
client_runtime_id 🔒
The ID a TUI offers its machine’s runtime under: client_ and the host name, sanitized as host_runtime_id does.
run_attached_tui 🔒
cookie attach: connects to the daemon at url, failing rather than running one in this process, and runs the TUI against it.
run_daemon_tui 🔒
Runs the TUI against the daemon client reaches at url, connected and handshaken as identity, as cookie attach and plain cookie with a running daemon both do: sessions use the runtime local_daemon::runtime_for chooses, a dropped connection is redialed, and quitting leaves the daemon running.
run_local_frontend 🔒
Runs the TUI against the daemon runtime composes in this process, showing notices from the start.
run_plain 🔒
Plain cookie: the TUI against the daemon [server] describes when one answers, else against one composed in this process over workspace (always with standalone), starting a session in project when given.
start_dial_in 🔒
Offers the daemon at url this machine’s directory cwd as runtime id, dialed in for as long as this process runs: a daemon on another machine cannot see this one.
