The cookie command line: its arguments, and the dispatch to the module of each subcommand.

Modules§

agents 🔒
cookie agents: list a daemon’s agents with where each comes from, refresh its official agents, and check agent documents before publishing them (docs/site/specs/machines-on-demand.md section 2.1).
compose 🔒
Composing the daemon in this process: configuration, the models.dev catalog and its refresh loop, providers, the engine, and the official agents and skills kept up to date.
config 🔒
cookie config: read and change a daemon’s configuration (config.toml and the agent documents) with config.get, config.apply, and config.reload.
connect 🔒
cookie connect and cookie disconnect: choosing a provider, its auth method, setup values, and credentials at the terminal, and connecting or disconnecting it through the daemon. cookie onboard reuses the flow.
cron 🔒
cookie cron: list, show, create, edit, delete, enable, disable, and run a daemon’s cron jobs with the crons.* methods, so it works against a remote daemon (docs/site/specs/cron.md section 12).
daemon 🔒
cookie daemon: serving the composed daemon over WebSocket until a stop signal or a restart, and the token it serves with.
frontend 🔒
Plain cookie and cookie attach: the TUI against a running daemon, or against one composed in this process.
headless 🔒
cookie run: one prompt without the interactive TUI, against a daemon composed in this process (cookie_agent::run).
machine 🔒
cookie machine: list and regroup the machines a daemon’s runtimes run on with the machines.* methods, so it works against a remote daemon.
mcp 🔒
cookie mcp: listing MCP servers and authorizing a remote one over OAuth.
memory 🔒
cookie memory: list, show, edit, and delete a daemon’s memory files with the memory.* methods, so it works against a remote daemon (docs/site/specs/memory.md section 10). The listing and show give each memory’s stamps and its size against its limit (section 16.9); edit leaves out the stamp lines the daemon owns.
onboard 🔒
cookie onboard: set up a daemon, local or remote, through its onboarding API (docs/site/specs/default-models-and-onboarding.md section 7, and docs/site/specs/machines-on-demand.md section 2.2): connect a provider when none is, choose default_model, and optionally small_model and utility_model. The daemon fetches its official agents as it finishes; there is no starter kit. It writes nothing itself; the daemon does.
project 🔒
cookie project: list, create, rename, delete, and edit a daemon’s projects with the project.* methods, so it works against a remote daemon (docs/site/specs/projects.md section 10.2).
runtime 🔒
cookie runtime: serving this machine’s coding runtime over stdio or dialed in to a daemon, and the MCP bridge ACP agents start.
sessions 🔒
cookie sessions: converting session logs to this build’s history format.
skills 🔒
cookie skills: list a daemon’s skills with where each comes from, refresh its official skills, and check skills before publishing them (docs/site/specs/default-models-and-onboarding.md section 13).
update 🔒
cookie update (alias cookie upgrade): replaces this binary with the newest release on the channel it was installed from (docs/site/specs/self-update.md).
web 🔒
cookie web: the daemon’s web page with its token.
