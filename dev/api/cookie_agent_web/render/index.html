Module render

Expand description

The transcript as HTML: pure functions from the shared client state to markup the page inserts as is. Everything a model, a tool, or a user wrote is escaped here, so no input can add markup of its own; the only markup is what these functions write. Interactive parts carry data-action attributes, which one click handler on the transcript dispatches.

Modules§

blocks
Display blocks as HTML, one renderer per kind. A renderer never looks at which tool made a block; a block of a kind this build does not know renders as nothing, as in the TUI (the daemon already sends an older client a newer kind as its text fallback).
budget
The row budget of a tool’s output, as in the TUI: an expanded call shows its first lines and says how many more there are; a click on that shows up to the larger budget. The budget counts lines as the blocks show them, whatever their kind, and never looks at the tool.
markdown
Markdown to HTML from the shared [MarkdownDocument]’s events. Raw HTML in the text is escaped and shown as written, never rendered; links go only where super::safe_link allows and open in a new tab; images are shown as links, so a page never loads a remote image on its own; code blocks carry their language for the highlighter.
sgr
SGR colour sequences in terminal display blocks, as styled spans. The daemon strips every control sequence from terminal output except SGR (ESC [ <params> m), so the only state is the graphic rendition those sequences set, which carries across lines as in a terminal.
transcript
A session’s transcript items as HTML, from the shared reducer’s projection. Each item renders on its own, so the page re-renders only the items whose item_key changed; an assistant reply renders part by part (transcript_rows), so a streaming reply draws again only the parts that changed, and its text only its open tail.
