The Cookie Agent web client: a Leptos page rendered in the browser (client-side), speaking the client protocol through cookie_agent_protocol’s browser transport. scripts/build-web.sh builds it with Trunk; cookie daemon serves the result.

The crate also compiles natively, so the workspace builds without the wasm target; its tests cover the pure logic only.

Modules§

agents
The Agents view’s list: the agent documents of config.get, the shared ones first, then each preset with its agents, and what a row shows of a document: its description, its mode, and whether it is enabled, read from the document’s frontmatter.
attach
Attaching files in the page: what the model accepts, as an accept attribute, and how far an image must shrink to fit its limits before it is offered downscaled.
badges
Where a session runs, as its row shows it: the badges of client_state::badges, each machine in its stable hue (the hue-* theme tokens in style/main.css), and the hue’s dot that marks a runtime, in its machine’s colour, in the bottom bar and on the runtime cards.
browser
The few browser services the page uses: its address, storage, history, the colour scheme, visibility, and installing the page as an app. Everything here is a thin call into web_sys; it compiles on every target but only works in a browser.
cards
The new-session runtime cards, independent of the browser: one card per runtime capability that takes a workspace, plus global, grouped by the machine each runtime runs on; which cards a new session selects and at which workspaces; the defaults, the workspace suggestions, the note about tool-name prefixes, and what the browser remembers.
commands
The session’s commands, as the title bar’s ⋮ menu lists them. The web composer has no slash commands: text that starts with / is a message like any other, and every command is a menu entry with a readable name, an icon, and a line saying what it does. Commands with somewhere else to live are not here: the bottom bar picks the agent, the model, and the permission mode, the composer attaches and stops, the sessions list starts and opens sessions, and the rail opens the daemon-wide views.
connect
The connect screen’s decisions, independent of the browser (spec 7.2, 7.3): the daemon URL a page fills in from its own address, the token a #token= fragment carries, what a launch starts from, whether to connect without a click, and the hint for a connection refused before its handshake.
connection
Opening the daemon connection from the page, with the tab’s identity.
emoji
The project editor’s emoji picker list (docs/site/specs/projects.md section 10.3): a few hundred common emoji by category, each with its Unicode name for the search box. Names and code points only: the emoji draw in the system font.
errors
How the page says what went wrong. A daemon error is drawn from its fields (its message, its hint, and its detail), never from the error’s display text, which already joins the message and the hint: a page that showed that text and then the hint said the hint twice. Each part is sanitized as the protocol’s own display text is.
format
Short forms the page shows where room is tight: a directory’s last component, how long ago something happened, a token count, and a cost.
goal
The root session’s goal: what the goal sheet asks for, and which lifecycle actions the goal bar offers, as the TUI’s bar does.
icons
The page’s icons: Font Awesome Free 6, whose artwork is CC BY 4.0, from the icondata crate. Components show them through leptos_icons; the transcript, which renders to HTML text, inlines the same SVG. Each icon is a static the linker keeps only when the page names it.
install
Installing the page as an app (spec 9), independent of the browser: which offer the page makes from what the browser says about itself.
keys
What a key does in the composer, as in the TUI: Enter steers, Alt+Enter queues, Shift+Enter, Ctrl+Enter, and Ctrl+J insert a newline, Escape cancels, and Up in an empty composer recalls this client’s newest pending or queued message. Also which buttons the composer shows, and how tall its text grows.
layout
Where the page is, independent of the browser: the rail’s views, the Settings sections, the history entries browser Back closes, and the press that offers to delete a session row on a touch screen. The session’s ⋮ menu is crate::commands.
machines
The Machines & runtimes view’s rules, independent of the browser: the gesture that drags a runtime to another machine (a mouse drags at once, a finger after a long press), the machine a drop moves it to, the [runtimes.<id>] template an ssh form writes, the command a runtime dials in with, and the guides the view links to.
memory
The Memory view’s project folders: the shared rows (cookie_agent_client_state::memory) with each project a folder that folds, folded until this browser opened it, and what deleting a project deletes: its memories, never the other files in its folder.
modes
The permission modes the bottom bar’s mode picker lists, with the names and one-line descriptions of the permissions guide (docs/site/concepts/permissions.md).
oauth
Signing in to MCP servers from the page (spec): the OAuth redirect is the page itself with ?oauth=callback, the sign-ins this browser started are kept by their state, and a tab the authorization server sends back hands its address to the tab that started the sign-in over a BroadcastChannel, or finishes the sign-in itself.
panics
Panics, made visible. The page is built with panic = "abort", so a panic is a WebAssembly trap whose console line (“RuntimeError: unreachable”) says nothing of what failed. The hook install sets first logs the panic’s message and location, with the JavaScript stack, to console.error.
places
Where sessions work, as text: a session’s runtimes and workspaces (SessionMeta.attachments) in the bottom bar, and its directory (cwd_identity, its first workspace) in the sessions filter, named by its runtime. (The session rows show them as badges, client_state::badges.) Every path shows under its runtime’s home (~/…) with the shared client_state::paths rule, and absolute where the runtime reported no home.
render
The transcript as HTML: pure functions from the shared client state to markup the page inserts as is. Everything a model, a tool, or a user wrote is escaped here, so no input can add markup of its own; the only markup is what these functions write. Interactive parts carry data-action attributes, which one click handler on the transcript dispatches.
skills
/skills: which skills a search shows, ranked as the TUI ranks them.
theme
The light or dark theme: the system’s, or the user’s override kept in localStorage.
tree
The subagents nested under their session in the sessions list: which rows the open session’s tree shows, collapsed or expanded, the title bar’s path to a viewed subagent, and the subagent a delegate call started.
workspace
The connected page’s state and what it does with the daemon: the session list, the viewed session’s projection (the shared reducer), its subscriptions, the composer, approvals, the model draft, the permission mode, and usage. It mirrors the TUI, with the same calls and the same shared client behaviour from cookie_agent_client_state; timers run on the browser’s event loop.
